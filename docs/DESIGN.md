# 내 비서 — 업무지시 · 알람 · 캘린더 · 일기장 (설계, 2026-09-15)

> 대표님 요청: "나 개인이 스스로 사용할 업무지시랑 알림 일기장. 캘린더 · 날짜시간 알람 · 진행중/마감 체크 ·
> 날짜 계속 변경 · 반복 알람 · 알람마다 메시지 · 일기장 · 캘린더에 적으면 그 시간에 알람 · 울릴 때 마감/진행으로
> 날짜 변경 · 모든 것 수정·삭제 · PC 와 휴대폰 · PC 는 화면이 깜빡이는 알림 · 휴대폰은 진동(징징징 3번)과 소리.
> **PC 가 꺼져 있어도 알람이 와야 한다** — 가장 간단한 방법으로."

## 1. 방식 — PC 가 꺼져 있어도 울리는 이유

알람을 **보내는 쪽이 인터넷에 늘 켜져 있어야** 합니다. 이미 갖고 계신 무료 계정 두 개로 해결합니다.

| 무엇 | 어디서 | 비용 |
|---|---|---|
| 자료(일정 · 알람 · 일기 · 휴대폰 등록) | **Supabase**(서울, 이미 있는 프로젝트 `Ai-office`) — 표 4개, 본인만 읽고 쓰는 잠금(RLS) | 무료 |
| 알람 보내기 | Supabase 안의 **1분마다 도는 시계(pg_cron)** 가 "보낼 알람 있나" 를 물어보고, **작은 함수(Edge Function)** 가 등록된 휴대폰·PC 로 웹 푸시를 보냄 | 무료 |
| 화면(앱) | **GitHub Pages**(공개 저장소 `Ai-office-mcare/my-secretary`) — 휴대폰 홈 화면에 추가하면 앱처럼 | 무료 |

PC 를 꺼도 Supabase 가 대신 보냅니다. 서버 설치도, 터널도 없습니다. 이 PC 는 **화면 하나(브라우저)** 일 뿐입니다.

## 2. 자료 구조 (Supabase, 표 이름 앞에 `sec_`)

| 표 | 무엇 |
|---|---|
| `sec_items` | 일정·업무지시·알람 한 건. 제목 · 메모(알람 메시지) · 언제(`due_at`) · 반복(`repeat`: none/daily/weekdays/weekly/monthly · `repeat_days` 요일) · 상태(`status`: todo/doing/done/closed) · 알림 켬(`notify`) · 다음 울릴 시각(`next_fire_at`) · 마지막 울린 시각 |
| `sec_diary` | 일기 — 날짜 하나에 글 하나 |
| `sec_push_subscriptions` | 알림 받을 기기(휴대폰·PC 크롬) |
| `sec_alarm_log` | 울린 기록 (몇 시에 어느 기기로, 성공/실패) |

모든 표는 `user_id = auth.uid()` 인 줄만 보이고 고쳐집니다. 로그인은 Supabase 이메일·비밀번호.

## 3. 알람이 도는 순서

```
[캘린더에 일정 저장]  → due_at = 그 날짜·시간, next_fire_at = due_at
[1분마다 cron] → Edge Function 'sec-send-alarms' 호출 (비밀 머리표로만 열림)
   → next_fire_at <= 지금 이고 status 가 todo/doing 인 것을 골라
   → 그 사람의 등록 기기 전부에 웹 푸시 (제목 · 메시지 · 진동 [400,200,400,200,400])
   → 반복이면 next_fire_at 을 다음 회차로, 아니면 비움. sec_alarm_log 에 기록
[휴대폰 알림을 누르면] 앱이 그 알람 카드로 열림
   → [완료] [진행 → 1시간 뒤 / 내일 / 날짜 직접] [마감] 단추로 그 자리에서 날짜·상태 변경
```

반복 다음 회차 계산은 **한국 시간** 기준(매일 = +1일 같은 시각 · 평일 = 다음 월~금 · 매주 = 고른 요일 · 매월 = 같은 날짜).

## 4. 화면 (PWA, 한 파일 앱)

- **캘린더**(월) — 날짜마다 점(일정 수 · 일기 있음). 날짜를 누르면 아래에 그날 목록 + [+ 추가] + 일기.
- **일정 편집** — 제목 · 메시지 · 날짜 · 시간 · 반복 · 알림 켬 · 상태. 저장 · 삭제.
- **오늘/할 일** — 지난 것부터, 상태별. 카드에서 완료/진행/마감, 날짜 바꾸기.
- **일기장** — 날짜별 글. 자동 저장.
- **설정** — [이 기기에서 알림 받기] · 시험 알림 · 로그아웃.
- 앱이 열려 있을 때 알람 시각이 되면 **화면 전체가 빨강·흰색으로 깜빡이고 소리**(PC 용) + `navigator.vibrate([400,200,400,200,400])`(휴대폰).
- 앱을 닫아 두면 **웹 푸시**로 옵니다(휴대폰 · PC 크롬 모두). 푸시 소리는 기기 기본 알림음(웹 방식의 한계).

## 5. 솔직한 한계

- 웹 푸시는 **크롬(안드로이드) 기준**. 아이폰은 홈 화면에 추가한 뒤에만 됩니다.
- 푸시 알림음을 우리 소리로 바꾸는 것은 안드로이드 크롬에서 안 됩니다(앱이 열려 있을 때만 우리 소리).
- Supabase 무료 프로젝트는 1주일간 아무 활동이 없으면 잠듭니다 — 1분마다 도는 시계가 있어 잠들지 않습니다.
- 알람 정확도는 **1분 단위**입니다.

## 6. 만들 파일



## 알람시계 방식 (2026-09-20 대표님 요청)

"알람시계처럼 — 알람 때마다 20초씩 울리고, 변경하거나 마무리하지 않으면 5분마다 반복."

| 상황 | 동작 |
|---|---|
| 알람 시각 | 휴대폰 푸시(긴 진동 20초 무늬) + 앱이 열려 있으면 20초 소리·진동·깜빡임 |
| 완료·마감·날짜 바꾸기·1시간 뒤 중 하나를 안 하면 | **5분 뒤 다시** — "(2번째 알림)" … 최대 **12번(1시간)** |
| 12번 뒤에도 처리 없음 | 반복 없음: 멈춤(목록의 지난 일정) · 반복: 다음 회차로 넘어감 |
| 반복 알람에서 [완료] | "오늘 것 끝" → 다음 회차로 넘기고 계속 예정 (전에는 반복 자체가 죽었음) |
| [마감] | 반복이라도 통째로 끝 |

구현: `supabase/functions/sec-send-alarms/plan.js` (서버 함수·앱이 같은 파일) · 시험 `node --test tests/`.
몇 번째 울림인지는 칸을 추가하지 않고 `sec_alarm_log` 에서 이번 회차(due_at) 이후 기록 수로 센다 — 날짜를 바꾸면 저절로 0 부터.
앱: `startFlash` 20초 뒤 자동 멈춤 · 서버가 다시 울리면(`last_fired_at` 바뀜) 푸시가 없는 PC 에서도 다시 욺 · 푸시 ttl 5분.
바꾸려면: `plan.js` 의 `RING_SECONDS` · `NAG_INTERVAL_MIN` · `NAG_MAX`.
